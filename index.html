⚛️ 리액트가 탄생한 배경을 직접 체험하는 저장소

2011년 페이스북 광고팀의 고통에서 시작해, 2013년 5월 JSConf US에서 세상에 나온 React.
"문제 상황 → 리액트로 해결 → 트레이드오프" 순서로, 코드를 직접 짜면서 체감합니다.
각 미션의 자세한 설명은 missions/ 폴더 안의 README.md, 전체 가이드는 루트 README.md를 참고하세요.

CHAPTER 1 · 문제 (리액트 이전)

미션 1 · DOM 지옥에서 살아남기

바닐라 JS로 할 일 앱을 만들며, 데이터와 화면을 사람이 일일이 동기화해야 하는 2011년의 고통을 체감합니다.

 CHAPTER 2 · 해결 (리액트)

미션 2 · 같은 앱을 React로 다시 짜기

미션 1과 똑같은 앱을 선언형으로 다시 만들며 "갱신 코드가 사라지는" 마법을 체감합니다.

 CHAPTER 2 · 해결 (리액트)

미션 3 · 상태 끌어올리기 (단방향 데이터 흐름)

서로 동기화되지 않는 두 입력의 버그를, "상태 끌어올리기"로 고치며 UI = f(state)를 체감합니다.

 CHAPTER 3 · 트레이드오프

미션 4 · 재렌더링의 비용 (10,000개 리스트)

바닐라의 부분 갱신 vs React의 전체 재렌더를 측정하고, memo와 key로 성능을 되찾는 과정을 체감합니다.

 CHAPTER 3 · 트레이드오프

미션 4-① · 바닐라 기준선 측정

React 없이 "필요한 곳만" 고치면 얼마나 빠른지 기준선을 직접 측정합니다.

 CHAPTER 3 · 트레이드오프

미션 5-① · 네이티브 폼의 자유

HTML 폼은 DOM이 값을 기억하므로 코드가 아주 짧습니다. 이게 React가 포기한 편의입니다.

 CHAPTER 3 · 트레이드오프

미션 5-② · 제어 컴포넌트의 대가

양방향 바인딩을 버린 React의 폼은 왜 이렇게 코드가 길어졌을까요? 매 키입력의 재렌더를 측정합니다.

 CHAPTER 3 · 트레이드오프

미션 6 · 훅(Hooks)의 함정

고장 난 타이머를 고치며 상태 스냅샷, 클로저, 의존성 배열이라는 새로운 인지 비용을 체감합니다.
