- '미션 1의 이벤트 위임(closest('li'), dataset.id)이 사라졌는지 보세요' -> 미션 1에서 closest가 필요한 이유는 화면을 업데이트할 때 `부모.innerHTML = ...`의 형태로 하기 떄문이다. 만약 1에서 이런 형식을 사용하지 않는다면 todo에 push할 때, 삭제할 때마다 이벤트 핸들러 바인딩, 해제와 같은 로직을 전부 작성해주어야 하므로 화면과 상태 불일치에 대한 위험은 똑같이 발생한다.
- `const percent = all === 0 ? 0 : (done / all) * 100;` 처럼 하는 이유는 all이 0인 경우에 대비하기 위해서이다. 분모인 all이 0이면 NaN이다.
- AddTodoForm의 handleSubmit에서 e.preventDefault를 해주는 이유는 폼 데이터를 제출하면 페이지 전체가 새로고침되는 기본 동작이 존재하기 때문이다.

### 돌아보기
1. setTodos 이후에 화면 갱신 코드가 한 줄도 없는데 화면이 바뀌는 이유는, 리액트에서 렌더링 트리거(setState)가 일어나면, 자동으로 하위의 모든 컴포넌트를 리렌더해주고, 변경된 부분이 실제 DOM에 반영되기 때문이다.
2. 불변성(`[...todos]`)이 필요한 이유는 리액트가 값을 비교하는 방식 때문이다. 만약 todos.push({...})의 형태로 상태를 업데이트하게 된다면 리액트가 안의 내용물을 일일이 깊은 비교를 해야하는데, 이는 비싼 작업이다. 따라서 리액트는 참조만 비교하는 방식으로 값을 비교하는데, 이를 위해서는 새 배열(`[...todos]`)을 만들어주어야 한다.
  - 이를 불변성이라고 하는 이유는, 기존 배열의 참조(todos)는 변경되지 않은 상태에서 스프레드를 통해 내부 값들을 복사하는 것이기 때문이다.
3. renderStats / renderList 등 갱신 호출 이 사라진 자리에는 setTodos라는 화면을 갱신하고자 하는 의도와, 어떤 화면을 고쳐야 하는지에 관련한 JSX 선언만 남았다.
